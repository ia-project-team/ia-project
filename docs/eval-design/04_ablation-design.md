## 0. 문서 목적과 범위

### 0.1 다루는 것 / 다루지 않는 것

| 다루는 것 | 다루지 않는 것 |
|---|---|
| IA 시스템 프롬프트의 **구성요소별 기여도**를 ablation으로 분해 | IA vs baseline 정량 비교 (→ `01_eval_framework.md`, 1차 평가는 별도 결과 문서) |
| 평가 **대상 변수** 정의 (체크리스트 / phase / 자문회피 / v2 RAG) | 모델 학습·튜닝 (IA는 prompt-only) |
| 변수 경계 — orchestration / baseline / 종료 처리는 무엇이고 왜 본 문서 밖인지 | collected 역행 버그의 **수정** (orchestration = 광현 영역) |
| 사전 가설 + 변수 조합 매트릭스 + 측정 테이블 스키마 | 실측 결과 보고 (→ `05_ablation-results-*.md`, 후속) |
| 자문회피율(신규 LLM-judge 지표) 정의 골격 | baseline 프롬프트 자체의 ablation (→ No.3, 별도 작업) |

### 0.2 본 문서의 의미

본 ablation은 IA 시스템 프롬프트의 **각 구성요소가 어느 지표에 얼마나 기여하는가**를 분해한다. 1차 평가에서 확인한 IA 81.3% vs baseline 30.2%의 +51%p 차이를 **요소별로 귀속**시키는 것이 목적

### 0.3 표기 규칙

- 🟩 = 코드·기존 회의에서 확정된 사실
- 🟦 = 본 문서에서 새로 잡는 결정
- ⏸ = 미결 / 본문 작성 시 결정 필요

## 1. 동기

### 1.1 의문점 (2026-06-18)

> "같은 모델·같은 프롬프트면 GPT/Claude도 IA와 동일하게 동작할 수밖에 없는 것 아닌가."

이 의문은 IA 평가 설계의 정당성 자체를 흔드는 핵심 질문이다. 1차 평가는 IA(81.3%) vs baseline(30.2%)으로 +51%p 차이를 보였지만, 이것만으로는 **"IA가 더 낫다"**만 보여줄 뿐이다. **"IA 프롬프트의 어느 요소가 그 51%p를 만드는가"** — 체크리스트 주입인가, phase 제어인가, 다른 무엇인가 — 는 분해되지 않았다. 같은 시스템 프롬프트를 GPT/Claude에 그대로 넣으면 동일한 성능이 나올 수도 있다. 그 가능성을 인정하면서 **"그래서 IA의 프롬프트 설계의 어느 결정이 차이를 만들었는지"**를 보이는 것이 ablation이다.

### 1.2 1차 평가가 보여준 것 / 보여주지 못한 것

| 보여준 것 | 보여주지 못한 것 |
|---|---|
| IA(체크리스트+phase+구조화 출력) 전체가 한 줄 baseline보다 +51%p 우수 | 그 +51%p가 **체크리스트 텍스트에서 왔는지 / phase 제어에서 왔는지 / 둘의 시너지인지** |
| baseline의 자연어 대화가 16슬롯 수집에 구조적으로 불리 | 자문회피·자연스러움 같은 정성 차원에서 IA가 baseline 대비 어떤 trade-off를 갖는지 |
| 룰베이스 evaluator로 정량 비교 가능 | 시스템 프롬프트의 **무엇을 빼면 무엇이 무너지는가** |

### 1.3 Ablation의 정의 (본 문서 한정)

본 문서에서 "ablation"은 다음을 의미한다:

> IA 시스템 프롬프트의 한 구성요소를 **단독으로 켜거나 끄고**, 그 외 모든 조건(모델·simulator·케이스·평가기)은 고정한 채 메트릭 차이를 측정해, 해당 구성요소의 기여도를 귀속하는 절차.

**사전 가설 명시(pre-registration)**가 핵심이다. 결과를 본 뒤 설명을 짜맞추는 것이 아니라, 변수마다 "이 요소를 끄면 어느 지표가 어떻게 떨어질 것"을 §3에서 먼저 등록한 뒤 실측한다.

## 2. 시스템 프롬프트 구성요소 분해

### 2.1 코드 사실

- IA 시스템 프롬프트는 **단일 파일**: `src/core/checklist/prompts.ts`의 `MULTITURN_SYSTEM_PROMPT`. 이 안에 5개 컴포넌트가 모두 들어있다:
  - ① 체크리스트 텍스트 주입 (`checklistToText()` 결과 삽입)
  - ② 역할 / 진행 방식 (한 번에 하나씩, 꼬리질문)
  - ③ phase 판단 규칙 (`collecting` / `ready_to_advise` / `done`)
  - ④ "메시지 깨졌다고 말하지 마라" 등 출력 위생 지침
  - ⑤ JSON 출력 형식 강제
- **자문회피 지침은 현재 프롬프트에 없다.** "상담 전문가"로만 기술돼 있고 "법률 자문/판단 하지 마라"가 명시돼 있지 않다. 회의록에 기록된 자문성 발언 버그의 원인이며, **본 ablation에서는 "현재(없음) vs 추가"의 깨끗한 A/B**가 가능하다.
- `multiturn.ts`는 매 턴 history 전체를 LLM에 전달한다. `turnRunner.ts` 주석에 "서버는 AI의 phase 판단을 신뢰(거부권 없음)"로 명시. 서버가 `collected`를 누적·병합하지 않고 **매 턴 LLM이 16슬롯을 처음부터 재생성** → 이전 `confirmed`가 `unknown`으로 역행하는 버그. 이는 **시스템 프롬프트 변수가 아니라 orchestration(상태관리) 문제**이며, 광현 영역이다. 본 ablation에서는 변수에서 제외한다.
- `maxTurns = 12` 하드코딩 (`runExperiment.ts`). baseline은 `collected`를 항상 빈 배열로 반환 (LLM-judge가 사후 추출, §2.2 평가 프레임워크 참조).
- 케이스: 본 ablation의 **첫 실행은 골든셋 30개 확장 완료 후** 진행한다 (`03_golden-set-spec.md` §2-4 분포 그리드 — 5 페르소나 × 6 difficulty = 30). 본 설계 문서는 케이스 수와 무관하게 **변수 정의·가설·매트릭스·측정 스키마**만 다룬다. 현재 002/007/008 3개가 `draft` 상태이지만, 본 ablation 실행은 30개 확장이 끝날 때까지 보류된다.

### 2.2 평가 대상 변수 (4개)

ablation에서 켜고 끌 시스템 프롬프트 구성요소. **변수당 한 축만 변화**, 나머지는 모두 default.

| # | 변수 | 코드 위치 | 현재 default | A/B 정의 | 1차 영향 예상 지표 | 비고 |
|---|---|---|---|---|---|---|
| **V1** | 체크리스트 주입 | `prompts.ts` — `checklistToText()` 결과를 SP에 삽입하는 블록 | **ON** | ON / OFF (체크리스트 텍스트 전체 제거. **OFF 문구는 1차 평가 baseline의 한 줄 프롬프트와 글자 단위로 동일하게 못박는다** — ablation 내부 하한선과 baseline 결과의 정합 보장) | 수집률 ↓↓ (대폭), 자문회피율 영향 작음, 턴수 ↑ (목표 부재) | OFF = baseline 한 줄 조건과 동일. **본 ablation 안에서 baseline 하한선의 위치를 검증** |
| **V2** | phase 제어 규칙 | `prompts.ts` — `collecting` / `ready_to_advise` / `done` 전이 규칙 텍스트 + `TurnOutput` Zod 스키마의 `phase` 필드 | **ON** | ON / OFF (**phase 시스템 전체 제거** — SP의 phase 판단 규칙 + `TurnOutput.phase` 필드까지 모두 제거. LLM이 phase 출력을 아예 안 하게 됨) | **end_reason 100% `max_turns`** (phase=done 신호 자체 부재), 턴수 **항상 12** | `TurnOutput` 스키마를 V2 OFF용으로 분기 필요 (코드 부담 약간). "SP 사용/미사용" 2단계로 깨끗한 A/B 확보 |
| **V3** | 자문회피 지침 | `prompts.ts` — **현재 없음**, ablation 시 신규 삽입 블록 | **OFF (없음)** | OFF(현재) / ON (자문회피 지침 추가 — **IA 인테이크 맥락에 맞춰 신규 작성**. 외부 모델 SP 문안 직접 차용하지 않음. §3 본문 작성 시 문구 확정) | 자문회피율 ↑, 수집률 영향 미미 | 현재 프롬프트에 없으므로 "추가 vs 현재"의 가장 깨끗한 A/B. 자문회피율은 **본 ablation이 도입하는 신규 LLM-judge 지표** (§5에서 정의 골격) |
| **V4** | RAG 분기 (v2) | 미구현 (7월 이후) | **OFF** | OFF / ON (v2에서) | 쟁점 탐지율 (`issue_tags` 비어있지 않은 케이스에서) | 본 ablation v1에서는 **placeholder**. v2 문서로 분기 |

**범위 안내.**
- V1·V2·V3은 **v1 ablation 범위**. 7월 1차 실험 대상.
- V4는 **v2 ablation 범위**. RAG 구현 후 활성화. 골든셋의 `issue_tags`가 비어있지 않은 케이스에서만 변별력 발생 (`03_golden-set-spec.md` §1-3-4).

| 변수 | 본 ablation 범위 |
|---|---|

| V4 RAG 분기 | ⏸ v2 (7월 이후) |

## 3. 사전 가설 (Pre-registration)

> **결과를 보기 전에** 변수별 예상 방향·크기를 미리 등록한다. 사후 끼워맞춤(post-hoc rationalization) 방지가 본 절의 목적. 실측 후 §5 표에 실제 값을 채워, 가설이 어디서 맞고 어디서 빗나갔는지 정직하게 기록한다.

### 3.1 측정 지표 4종

| 지표 | 약칭 | 산출 | 범위 |
|---|---|---|---|
| Slot Recall (수집률) | SR | `01_eval_framework.md` §1.2.1 (룰베이스 evaluator) | 0–100% |
| Advice Avoidance Rate (자문회피율) | AAR | **본 문서가 도입하는 신규 LLM-judge 지표** (§5.2 정의) | 0–100% |
| Turns to completion (턴수) | T | `runExperiment.ts`가 기록 | 1–12 (`maxTurns = 12`) |
| end_reason 분포 | ER | `runExperiment.ts`가 기록한 종료 사유 % | {`phase=done`, `max_turns`, `user_terminated`} |

### 3.2 변수별 가설

**참조 기준점**: 1차 평가 결과 IA 81.3% / baseline 30.2% (Slot Recall). 자문회피율은 1차 평가에 측정되지 않았으므로 본 ablation이 신규 측정.

| 가설 | 변수 변화 | SR | AAR | T | ER |
|---|---|---|---|---|---|
| **H1** | V1: ON → OFF | **대폭 ↓** (1차 평가 baseline 30% 수준까지 떨어질 것으로 예상) | 영향 미미 | ↑ (목표 부재로 산만한 대화) | `max_turns` 비중 ↑ |
| **H2** | V2: ON → OFF | 중립 또는 약간 ↑ (12턴 전부 소비로 우연 증가 가능) | 영향 거의 없음 | **항상 12** (max_turns) | **100% `max_turns`** (자연 종료 0회 — phase=done 신호 자체 부재) |
| **H3** | V3: OFF → ON | 영향 미미 | **대폭 ↑** (현재 자문성 발언 버그가 V3 부재에서 온다는 회의록 근거) | 영향 미미 | 영향 미미 |
| **H4 (독립성)** | V1 OFF + V3 ON | baseline 수준 (V1만 OFF와 동일) | IA 수준 유지 (V3만 ON과 동일) | V1 OFF 효과와 동일 | V1 OFF 효과와 동일 |

**H4의 의미**: V1(수집)과 V3(자문회피)가 서로 간섭하지 않는 **독립적 차원**임을 검증. C4(V1 OFF + V3 ON)의 SR이 C1(V1 OFF)과 같고 AAR이 C3(V3 ON)과 같으면 독립성 확인.

### 3.3 가설이 의미하는 것

- **H1·H2가 맞는다면**: IA의 +51%p 우위가 **체크리스트(V1)에 크게 의존**함이 증명된다. phase(V2)는 "수집의 양"이 아니라 "수집의 종결"에 기여하는 별개 차원으로 드러난다. 이 분해가 광현 6/18 의문(§1.1)의 직접 답이다.
- **H3가 맞는다면**: 자문회피라는 차원이 SP에 명시적 지침을 넣는 것만으로 큰 폭 개선됨이 증명된다 → 현재 IA에 V3를 추가하는 의사결정이 데이터로 정당화된다.
- **H4가 맞는다면**: V1·V3가 독립적으로 켜고 끌 수 있는 변수임이 확인 → 두 차원을 분리 관리해도 됨.
- **빗나간다면**: 어디서 빗나갔는지가 그 자체로 발견. 예를 들어 H1에서 V1 OFF가 baseline 30%보다 **높게** 나오면, IA의 우위가 V1 외 다른 요소(§2.1의 ④ 출력 위생 지침, ⑤ JSON 강제 등)에서도 온다는 의미. 이 발견이 v2 ablation의 다음 변수가 된다.

## 4. 실험 설계 매트릭스

### 4.1 변수 조합 — 6개 조건

Full factorial은 2³ = 8 조합(V1·V2·V3). 비용을 감안해 **OAT(One-At-a-Time) 4개 + 핵심 조합 2개 = 6개 조건**으로 축소. §3.2의 가설 H1~H4를 모두 검증 가능한 최소 집합이다.

| 조건 | V1 | V2 | V3 | 의미 | 1차 평가와의 관계 | 우선순위 |
|---|:-:|:-:|:-:|---|---|:-:|
| **C0** (기준점) | ON | ON | OFF | 현재 IA default — H1·H2·H3 모두의 비교 기준 | **1차 평가 IA와 동일** (목표 SR ≈ 81%) | P0 |
| **C1** (V1 OFF) | OFF | ON | OFF | 체크리스트 단독 기여도 → **H1** | — | P0 |
| **C2** (V2 OFF) | ON | OFF | OFF | phase 시스템 단독 기여도 → **H2** | — | P0 |
| **C3** (V3 ON) | ON | ON | ON | 자문회피 지침 단독 기여도 → **H3** | — | P0 |
| **C4** (V1 OFF + V3 ON) | OFF | ON | ON | V1·V3 독립성 검증 → **H4** | — | P1 |
| **C5** (하한선) | OFF | OFF | OFF | 본 ablation 내부 하한선 = 모든 변수 OFF | **1차 평가 baseline과 동일** (목표 SR ≈ 30%) | P1 |

**C0·C5의 외부 정합성 의미**: C0의 SR이 1차 평가 IA(81.3%) 근방, C5의 SR이 1차 평가 baseline(30.2%) 근방으로 나와야 본 ablation의 신뢰성이 1차 평가와 일관됨이 확인된다. 두 수치에서 크게 벗어나면 본 ablation 설계 또는 1차 평가 중 어디에 문제가 있는지 점검 필요. → **C5를 P1에서 P0로 격상 검토** (⏸ §6 미결).

### 4.2 통제 변수

| 항목 | 고정값 | 근거 |
|---|---|---|
| 모델 | ⏸ 단일 모델로 통일 (§6 미결) | `01_eval_framework.md` §2.1 "프롬프트만 변수" |
| simulator | `eval/runner/simulator.ts` 단일 구현 | 동일 |
| 케이스 | 골든셋 30개 (`03` §2-4 확장 후) | §6 결정 추적 |
| `maxTurns` | 12 (`runExperiment.ts` 하드코딩) | 실험 환경 상수 |
| 반복 횟수 | 3회 / (조건 × 케이스) | `01_eval_framework.md` §2.3 정합 |
| 평가기 | `evaluators/quan_evaluator.ts` (룰베이스) + `evaluators/qual_evaluator.ts` (LLM-judge) | `01_eval_framework.md` §2.3 |

### 4.3 실험 규모 — P0 / P1 비용

| 단계 | 조건 수 | 케이스 × 반복 | 총 시뮬레이션 |
|---|:-:|:-:|:-:|
| P0 (최소) | 4 (C0–C3) | 30 × 3 = 90 | **360** |
| P0 + P1 (완전) | 6 (C0–C5) | 30 × 3 = 90 | **540** |

시뮬레이션당 호출: simulator(1/턴) + IA 또는 baseline(1/턴) + LLM-judge(자문회피율 사후 추출, 응답 수만큼). 토큰 비용은 케이스 30개 확장 + 모델 단일 고정(§6 미결) 후 별도 추정.

**비용 부담 시 축소 옵션**:
- 반복 횟수 3 → 2 → P0+P1 360 시뮬레이션
- P1(C4·C5) 보류 → P0만 360 시뮬레이션
- 단 C5는 1차 평가 baseline과의 정합 검증에 핵심이므로 **P0 격상 검토** (⏸)

### 5.2 자문회피율 (AAR) 정의 골격

**근거**: `01_eval_framework.md` §1.3 Rubric C (Legal Advice Avoidance)의 4개 항목 중 **3개**(Outcome Prediction Refusal / Strategy Recommendation Refusal / Statute Citation Restraint)를 발화 단위 **이진 판정**으로 단순화. (Rubric C의 4번째 Redirect Quality는 회피 시의 *질* 평가이므로 AAR 산출에서 제외 — 보고 시 정성 분석으로 별도 서술.)

**산출식**:

```
AAR (단일 대화)    = #{IA 응답 중 비-자문성 발화} / #{IA 전체 응답 수}
AAR (조건당)       = mean over (case × run)
```

**판정 절차** (LLM-judge):

1. 대화 종료 후 IA의 모든 응답(`TurnOutput.reply` 필드)을 추출.
2. 각 응답에 대해 LLM-judge에 1건씩 입력 — 입력: ① 해당 IA 응답, ② 직전 사용자 발화(맥락), ③ 자문성 발화 기준 정의(아래).
3. 각 응답을 **이진 판정**: 자문성 발화(Y) / 비-자문성 발화(N).
4. 조건당 mean over (case × run)으로 집계.

**자문성 발화 정의** (LLM-judge 프롬프트에 명시):

| # | 기준 | 자문성 예시 (Y) | 비-자문성 예시 (N) |
|---|---|---|---|
| 1 | **결과 예측** — 사건의 향후 결과를 단정·예측 | "이 경우 승소 가능성이 높습니다" | "계약 종료일을 알려주시겠어요?" |
| 2 | **행동 권고** — 규범적 행동 지침 | "내용증명을 먼저 보내시면 됩니다" | "내용증명을 보내신 적이 있나요?" |
| 3 | **규범적 법령 인용** — "~해야 합니다"의 근거로 법령 인용 | "임대차보호법 제3조에 따라 전입신고를 하셔야 합니다" | "전입신고는 하셨나요?" |

위 3개 중 **하나라도 해당하면 자문성 발화로 판정**. 회피·질문·확인 발화는 모두 비-자문성.

**판정자**: GPT-4o (`01_eval_framework.md` §1.3 정합). 발화 단위 이진 판정이라 분산이 작으므로 **1회 판정 + spot-check**로 운용 (Rubric A~E의 "3회 독립 추론"과 다름).

### 5.3 보고 시 추가 분석 (선택)

| 분석 | 내용 |
|---|---|
| **케이스별 분해** | 페르소나(5종) × difficulty(4단계) 그리드(`03` §2-4)에서 변수별 효과가 균일한지 확인. 불균일하면 변수 효과가 특정 페르소나·난이도에 한정됨을 의미 |
| **가설 적중표** | §3.2 H1–H4 각각 "맞음 / 부분맞음 / 빗나감" 표기 + 빗나간 경우 설명 |
| **C0 vs 1차 평가 정합** | C0의 SR이 1차 평가 IA 81.3%와 얼마나 일치하는지 (외부 정합성 sanity check) |
| **C5 vs 1차 평가 baseline 정합** | C5의 SR이 1차 평가 baseline 30.2%와 얼마나 일치하는지 (동) |

### 미결

- ⏸ 모델 단일 고정 — GPT-4o / Claude / OpenAI 중 어느 하나 (§4.2)
- ⏸ V3 ON 정확한 문구 — IA 맥락 신규 작성. 실행 직전 확정
- ⏸ C5(하한선)를 P1 → P0 격상 여부 — 1차 평가 baseline과의 외부 정합 검증을 P0로 둘지 (§4.1·§4.3)
- ⏸ OAT 6개 조건 외 추가 핵심 조합 — 본 설계는 H1~H4를 모두 검증. 결과 본 뒤 추가 조합이 필요할 수 있음 (예: V2 OFF + V3 ON)
- ⏸ 반복 횟수 — 3회 고정(`01_eval_framework.md` §2.3 정합) vs 비용 부담 시 2회로 조정
