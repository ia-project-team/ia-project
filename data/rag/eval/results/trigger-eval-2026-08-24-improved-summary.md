# RAG 질문 트리거 개선 후 품질 검증

## 무엇을 확인했나

체크리스트 밖의 추가 쟁점을 위한 22개 RAG 질문 트리거가 다음 두 상황에서 제대로 동작하는지 확인했다.

- 조건을 모두 충족한 정상 문장 22개
- 핵심 조건 하나가 빠진 오탐 방지 문장 22개
- 각 문장을 3회 반복해 총 132건 실행

이번 검증 범위는 **22개 RAG 추가 질문의 검색·선별·최종 출력**이다. 체크리스트 16개를 끝까지 진행하는 전체 대화나 평가셋에 없는 새로운 표현 전체를 검증한 것은 아니다.

## 적용한 개선

1. 조건이 맞는 질문 트리거를 일반 벡터 검색 Top 16과 별도로 조회해 합쳤다.
2. 조건을 충족한 질문 트리거는 점수 컷과 후보 다양화 과정에서 탈락하지 않게 했다.
3. 적용 가능한 트리거가 하나면 Luna를 다시 호출하지 않고 저장된 원문 질문을 사용했다.
4. 여러 트리거가 함께 적용될 때만 Luna가 우선순위를 판단하게 했다.

## 실행 조건

- 모델: `gpt-5.6-luna`
- 임베딩: `text-embedding-3-small`
- 검색: Supabase 실제 RAG 데이터
- API 키: 프로젝트 `.env.local`에서만 로드
- zsh에 내보낸 키·모델·Supabase 설정: 실행 전에 모두 제외
- 자동 재시도: 0회
- 비용 안전 상한: $0.50

## 최종 판단

- 현재 22개 추가 쟁점 평가셋에서는 **필요한 질문을 모두 포착하면서 오탐 0건**을 달성했다.
- 기존 목표였던 정상 질문 정확도 95% 이상과 오탐 방지 100%를 모두 충족했다.
- 단일 트리거의 불필요한 Luna 호출이 줄어 품질뿐 아니라 비용과 평균 속도도 개선됐다.
- 다음 단계에서는 체크리스트 16개와 RAG 질문이 섞인 전체 대화 테스트, 그리고 같은 의미를 다르게 표현한 새 문장 테스트를 추가하는 것이 좋다.

## 결과 파일 관리

원본 JSON은 대화·토큰·비용이 포함된 일회성 실행 산출물이므로 로컬에만 보관하고 커밋하지 않는다.
재현 가능한 입력은 `data/rag/eval/trigger-pair-cases.json`, 실행기는
`scripts/eval-rag-triggers.ts`에 남긴다. 원본 실행 결과에는 인증정보가 포함되지 않은 것도 확인했다.
